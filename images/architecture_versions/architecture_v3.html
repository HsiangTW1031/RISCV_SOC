RISCV_SOC · ARCHITECTURE · v2.2.0

A RISC-V SoC, built from a vendored core outward

PicoRV32 supplies the CPU; everything downstream of it — the AXI4-Lite crossbar, the AES-128 accelerator, the DMA engine, and the peripheral set — is hand-written RTL, verified in simulation. v2.2.0 corrected the crossbar's decode-miss response from SLVERR to spec-correct DECERR, and added a diagnostic CSR + IRQ so firmware can observe it without polling.

DESIGN NOTES

  • DECERR vs SLVERR (v2.2.0). Decode-miss now returns spec-correct DECERR; writes to the xbar's own read-only CSR window still return SLVERR — the address is valid, the operation isn't.
  • Why a CSR + IRQ at all. picorv32_axi never checks BRESP/RRESP, so a bus error is otherwise invisible to firmware. The CSR latches the faulting address; irq bit 9 means "go read it" instead of polling.
  • One clock domain. JTAG's TCK is the only CDC boundary — double-flopped at the TAP.
  • Static decode. addr[31:28] selects region, addr[15:12] selects peripheral; the CSR window only decodes addr[2].
  • Non-standard IRQ. PicoRV32 uses custom getq/setq/retirq opcodes, not RISC-V CSR interrupts.
  • Why PicoRV32. YosysHQ's own core — synthesizes cleanly with zero SystemVerilog risk, leaving the AXI fabric as the differentiator.
